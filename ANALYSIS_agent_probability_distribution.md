# Анализ репозитория: управление распределением вероятностей агента через мидтрейнинг

## Контекст: три режима агентных траекторий

Анализ строится вокруг трёхрежимной модели, описывающей положение агентных траекторий относительно текущего распределения модели:

- **Режим 1** (вне support): $p_\theta(\tau) \approx 0$ — базовая модель не генерирует ничего похожего на агентное поведение. RL мёртв, SFT работает грубо.
- **Режим 2** (в support, но малая вероятность): модель знает формат после поверхностного SFT, но при длинном горизонте постоянно «сваливается» обратно в текстовое поведение. Совместная вероятность мала из-за мультипликативного эффекта.
- **Режим 3** (значимая вероятность): агентные траектории — естественная часть генерации. Целевое состояние после Agentic CPT.

## 1. AgentFounder: прямая реализация Agentic CPT (Режим 2 → Режим 3)

**Расположение:** `Agent/AgentFounder/`

Первая реализация Agentic Continual Pre-training в пайплайне обучения Deep Research агентов.

### Механизмы смещения распределения:

- **Двухстадийный CPT** (32K → 128K контексты): сначала модель учится удерживать агентное поведение на коротких горизонтах, затем масштабируется
- **Open-World Memory**: непрерывный поток данных трансформируется в «память» для синтеза QA-пар
- **FAS (Planning Action Synthesis)**: усиливает корреляцию между планом и точностью траектории — повышает $p_\theta$ на этапе планирования
- **FAS (Reasoning Action Synthesis)**: эмулирует логический вывод при полной информации — повышает $p_\theta$ на этапе рассуждения
- **HAS (Decision-Making Action Synthesis)**: траектории как многошаговые процессы принятия решений с полным исследованием reasoning-action пространства — повышает $p_\theta$ на каждом шаге решения

### Результат:
AgentFounder-30B (3.3B активных) превосходит модели с 671B параметрами. Кривая data scaling демонстрирует характеристики scaling law для агентных данных.

## 2. Диагностика «сваливания» (измерение Режима 2)

**Расположение:** `WebAgent/ParallelMuse/functionality_specified_partial_rollout.py`

### Инструменты измерения:
- Вычисление **энтропии на уровне токенов** для каждого шага (строки 113-157)
- Раздельная **perplexity для thinking** (`think_ppl`) **и tool-calls** (`tool_call_ppl`)
- `branch_high_uncertainty_steps()` (строки 285-317): выявление шагов с максимальной неопределённостью для ветвления
- Режим `mixed_ppl`: одновременное отслеживание неопределённости в рассуждениях и инструментальных вызовах

Это инструментарий для диагностики Режима 2: модель умеет выполнять отдельные шаги, но на определённых шагах entropy/PPL резко растёт — модель теряет нить агентного поведения.

## 3. Многостадийные пайплайны (лестница Режим 1 → 2 → 3)

| Проект | Режим 1→2 (SFT/cold start) | Режим 2→3 (RL/CPT) |
|---|---|---|
| **AgentFounder** | — | Agentic CPT (FAS + HAS) |
| **WebDancer** | 4 стадии: data→traj→SFT | RL через DAPO |
| **WebSailor** | RFT (rejection sampling FT) | DUPO |
| **WebSailor-V2** | SFT + SailorFog-QA-2 | Dual-environment RL |
| **WebResearcher** | RFT на точных траекториях | RLVR |
| **WebLeaper** | SFT с фильтрацией ISR/ISE | Hybrid Reward + GRPO |
| **WebResummer** | — | ReSum-GRPO |

Все пайплайны осознанно разделяют фазу «введения формата в support» (SFT) и фазу «усиления вероятности правильных траекторий» (RL).

## 4. Скаффолды для управления $p_\theta(\tau)$ при длинных горизонтах

### WebResearcher
Явно идентифицирует проблему «сваливания»:
- **Cognitive Workspace Suffocation**: линейное накопление контекста убивает reasoning
- **Irreversible Noise Contamination**: ошибки на ранних шагах отравляют траекторию
- **Решение**: декомпозиция на дискретные раунды (Think → Report → Action), где Report — сжатая память

### WebResummer (ReSum)
- Периодическое сжатие истории в компактное состояние
- **ReSum-GRPO**: сегментация длинных траекторий + трансляция trajectory-level advantages на сегменты

Оба подхода управляют $p_\theta(\tau)$: вместо произведения вероятностей по 30 шагам, скаффолд «перезапускает» контекст, превращая длинную траекторию в серию коротких.

- Теоретический анализ мёртвого RL в Режиме 1
- Код AgentFrontier (ZPD-guided data synthesis) — упомянут только как ссылка на arXiv

## 6. AgentFounder: детальный разбор

### 6.1 Проблема: «двойное бремя» (Dual-Burden)

Post-training подходы, строящиеся на модели общего назначения, системно проваливаются на агентных задачах. Причина — при post-training модель вынуждена *одновременно*:
1. Выучить разнообразные агентные паттерны поведения (tool calls, multi-step reasoning, planning)
2. Выровняться на экспертные демонстрации

Это создаёт **фундаментальный оптимизационный конфликт**.

В терминах трёх режимов: модель после базового pre-training находится в Режиме 1. Post-training (SFT) пытается перепрыгнуть сразу в Режим 3, но из-за dual-burden застревает в нестабильном Режиме 2.

### 6.2 Трёхстадийный пайплайн

```
Pre-training → Agentic CPT → Post-training (SFT → RL)
                ↑
        Новый этап — мидтрейнинг
```

Agentic CPT вставляется **между** pre-training и post-training. Его роль — развить базовые агентные способности *до* этапа fine-tuning.

### 6.3 Двухстадийный CPT

**Stage 1: 32K контекст**
- Модель учится на «коротких» агентных траекториях
- Цель: освоить базовые агентные паттерны — вызов инструментов, обработку ответов, планирование следующего шага

**Stage 2: 128K контекст**
- Масштабирование на полноценные длинные траектории
- Модель учится удерживать агентное поведение на горизонтах 15–30+ шагов
- Двухстадийная конфигурация даёт **+3.3% Pass@1 и +3.7% Pass@3** по сравнению с одностадийным CPT

Ключевой инсайт: учить полные long-context агентные данные критично — обучение на обрезанных последовательностях значительно хуже. Если модель видела только короткие фрагменты, она не научится удерживать $p_\theta$ агентного продолжения на длинных горизонтах.

### 6.4 Open-World Memory

Механизм трансформации «сырого» потока данных в тренировочные данные для CPT:

1. Непрерывно обновляемые потоки данных (новости, статьи, документы) поступают в систему
2. Система конвертирует их в структурированную «память» — базу знаний
3. Из этой памяти синтезируются QA-пары различных стилей
4. Результат — масштабируемый поток агентных тренировочных данных

Решает проблему дефицита агентных данных: реальных агентных траекторий почти нет, Open-World Memory позволяет синтезировать их в произвольных количествах.

### 6.5 FAS: First-order Action Synthesis

#### FAS-Planning (Planning Action Synthesis)
- **Вход:** QA-пара (вопрос + ответ)
- **Выход:** план поиска + reasoning chain
- **Механизм:** Из наблюдения о сильной корреляции между качеством начального планирования и точностью всей траектории
- **Что учит модель:** Перед вызовом инструментов составить план поиска. Повышает $p_\theta$ на первом (критическом) шаге траектории

#### FAS-Reasoning (Reasoning Action Synthesis)
- **Вход:** Вопрос + его источники знаний
- **Выход:** Цепочка логического вывода от источников к ответу
- **Механизм:** Эмулирует ситуацию «fully informed» reasoning — рассуждение при полной информации
- **Что учит модель:** Корректно обрабатывать найденную информацию. Повышает $p_\theta$ на шагах после получения tool response

### 6.6 HAS: Higher-order Action Synthesis

- **Вход:** Существующая агентная траектория (в т.ч. неуспешная)
- **Механизм:** На каждом шаге траектории разворачивается пространство альтернативных решений
- **Выход:** Граф решений (decision tree), где каждый узел — шаг, рёбра — альтернативные действия

Стандартный подход выбрасывает неуспешные траектории. HAS превращает *любую* траекторию в богатый тренировочный сигнал. HAS напрямую расширяет support модели в пространстве reasoning-action. Модель видит не одну «правильную» траекторию, а **всё пространство решений на каждом шаге**.

### 6.7 Data Scaling

Эксперименты от 0 до **315B токенов** CPT-данных:

- Производительность растёт **логарифмически** с объёмом данных
- Самый большой скачок — в первых ~15B токенов (переход Режим 1 → 2)
- После 15B рост продолжается более плавно (углубление в Режим 3)
- Кривая не выходит на плато даже на 315B

### 6.8 Результаты

AgentFounder-30B (3.3B активных, MoE):
- BrowseComp-en: **40.0%** (vs DeepSeek-V3.1: 30.0%)
- GAIA: **72.8%** (vs Claude-4-Sonnet: 68.3%)
- HLE: **31.5%** — первая open-source модель >30%
- Frames: **89.6%** (vs DeepSeek-R1: 82.0%)

Модель с 3.3B активных параметров обгоняет модели с 671B — CPT важнее размера модели для агентных задач.

### 6.9 Маппинг на трёхрежимную модель

| Этап пайплайна | Переход | Механизм |
|---|---|---|
| Base Pre-training | → Режим 1 | Текстовый корпус, нет агентных паттернов |
| **CPT Stage 1 (32K)** | Режим 1 → 2 | FAS: базовые агентные паттерны входят в support |
| **CPT Stage 2 (128K)** | Режим 2 → 3 | HAS: пространство решений на каждом шаге. Длинные траектории становятся сэмплируемыми |
| SFT (RFT) | Стабилизация в Режиме 3 | Выравнивание на экспертные демонстрации |
| RL (GRPO/DUPO) | Оптимизация внутри Режима 3 | Усиление вероятности *правильных* траекторий в уже сэмплируемом пространстве |

## Вывод

Репозиторий **эмпирически и инженерно** реализует управление смещением распределения через:
1. **CPT** (AgentFounder) как центральный механизм перехода Режим 1 → 2 → 3
2. **Измерение энтропии/PPL** для диагностики точек «сваливания»
3. **Скаффолд-дизайн** для поддержания $p_\theta$ в зоне сэмплируемости
4. **Структурированный синтез данных** по компонентам агентного поведения (FAS-Planning, FAS-Reasoning, HAS)
5. **Data scaling до 315B токенов** с логарифмическим ростом, подтверждающим scaling law для агентных данных

Формализация через три режима $p_\theta(\tau)$ не присутствует, но интуиция и инженерные решения полностью ей соответствуют. Ключевой тезис авторов — **dual-burden problem** — это по сути описание того, почему прямой прыжок из Режима 1 в Режим 3 через SFT невозможен.

## 7. Критический анализ: midtraining как фундаментальная причина vs. удобная упаковка

### 7.1 Четыре неразделённых конфаунда

#### Конфаунд 1: Данные vs. стадия обучения

**Что смешано:** FAS/HAS данные + CPT как стадия обучения. Отсутствует ablation вида «те же FAS/HAS данные, поданные как SFT вместо CPT» или «те же данные, подмешанные в основной pre-training».

**Контр-свидетельство из репозитория:** Все проекты WebAgent (WebDancer, WebSailor, WebLeaper, WebShaper) обучаются *без CPT*, используя только SFT + RL, и достигают конкурентных результатов на тех же бенчмарках. Все работают на 32K контексте с post-training only.

WebSailor-V2 достигает 35.3% на BrowseComp-EN (vs 40.0% AgentFounder) через dual-environment RL + SailorFog-QA-2 данные, без CPT. Разрыв в ~5 п.п. может объясняться как CPT, так и разницей в данных/скаффолдинге.

#### Конфаунд 2: Длинный контекст vs. агентные данные

Stage 2 CPT (128K) одновременно вводит расширение контекстного окна и длинные агентные траектории. Двухстадийный CPT даёт +3.3% Pass@1 vs одностадийный, но это сравнение «32K CPT» vs «32K+128K CPT» — не изолирует эффект контекста от эффекта данных.

Отсутствует: сравнение 128K context extension на обычных текстах vs 128K с агентными данными.

#### Конфаунд 3: Скаффолд vs. обучение

Модель поддерживает два inference-режима (ReAct и IterResearch-based Heavy Mode), но Heavy Mode не open-sourced (FAQ.md). Невозможно определить, сколько из результатов приходится на скаффолд, а сколько на CPT.

Из WebResummer: скаффолд ReSum даёт **+4.5% Pass@1** как универсальное улучшение и **+8.2%** с ReSum-GRPO. Эти числа *сопоставимы* с заявленным эффектом двухстадийного CPT (+3.3%), что усиливает подозрение, что часть успеха — скаффолдинг.

#### Конфаунд 4: Объём данных vs. стадия

Data scaling 0→315B показывает рост. Но дал бы тот же объём (315B токенов агентных данных) такой же рост, если подать его как часть pre-training mix, а не как отдельную стадию? CPT на 315B токенов — по сути ещё один раунд pre-training на специализированных данных. Разница между «midtraining» и «pre-training с агентными данными» может быть номинальной.

### 7.2 Что репозиторий всё-таки доказывает

1. **Агентные данные важны** — data scaling от 0 до 315B показывает монотонный рост
2. **Длинный контекст при обучении важен** — обрезанные траектории хуже полных
3. **Post-training alone оставляет gap** — Qwen3-30B-A3B baseline 0.5% vs AgentFounder 40.0% на BrowseComp-EN
4. **Dual-burden — наблюдаемый эффект, но не доказанный механизм** — не подтверждён ablation (напр., двухэтапный SFT: сначала паттерны, потом стиль — без CPT)

### 7.3 Что не доказано

- Что CPT *как стадия* даёт что-то, чего не может дать aggressive SFT с тем же объёмом и качеством данных
- Что dual-burden — оптимизационный конфликт, а не просто недостаточный объём данных при SFT
- Что эффект CPT нельзя воспроизвести скаффолдингом + более мощной моделью
- Что «midtraining» отличается от «pre-training с добавленными агентными данными» чем-то, кроме позиции в пайплайне

### 7.4 Наиболее честная интерпретация

Midtraining в текущем виде — это доказанно *работающая* комбинация: (специализированные агентные данные FAS/HAS) + (длинный контекст 128K) + (большой объём 315B токенов) + (отдельная стадия обучения до SFT/RL).

Но **необходимость именно отдельной стадии** (а не подмешивания тех же данных в pre-training или в aggressive SFT) — это claim, не подтверждённый контролируемыми экспериментами в репозитории.

## 8. Конкретные техники мидтрейнинга: подробный разбор по коду и данным

### 8.1 FAS-Planning (First-order Action Synthesis — Planning)

**Цель:** Учит модель составлять план *до* первого вызова инструмента.

**Процесс синтеза:**
1. Берётся QA-пара (формат из `WebDancer/datasets/sample_qa.jsonl`):
   ```json
   {"question": "Identify the superhero movie...", "answer": "league of extraordinary gentlemen", "tag": "e2hqa"}
   ```
2. Сильная модель-учитель генерирует план поиска: декомпозицию вопроса на подзадачи + reasoning chain от плана к ответу
3. Результат — тренировочный пример: `<think>план + reasoning</think><tool_call>первый вызов</tool_call>`

**Артефакт:** Выход виден в `sample_traj.jsonl` — первый `<think>` блок содержит планирование:
```
<think>Okay, let's tackle this question step by step.
The user is asking about a prestigious British equestrian event...
First, the figure associated with Christmas gift-giving...
Let me search for this.</think>
<tool_call>{"name":"search","arguments":{"query":["1964 British horse race..."]}}</tool_call>
```

### 8.2 FAS-Reasoning (First-order Action Synthesis — Reasoning)

**Цель:** Учит модель делать правильные выводы из уже найденной информации (fully informed setting).

**Процесс синтеза:**
1. Вопрос + его knowledge graph (формат из `WebShaper/data/webshaper.500.jsonl`):
   ```json
   {"question": "...", "answer": "12,000",
    "formalization": [["V@M","is opening match of","V@X"], ["V@X","has record for","C@10"]],
    "urls": ["https://en.wikipedia.org/wiki/..."]}
   ```
2. `formalization` — граф знаний с переменными (V@) и константами (C@). `urls` — источники.
3. Генерируется цепочка: «из документа A → факт X, из B → факт Y, X+Y → ответ Z»

### 8.3 HAS (Higher-order Action Synthesis — Decision-Making)

**Цель:** Превращает одну траекторию в дерево решений через PPL-guided ветвление.

**Реализация** (из `ParallelMuse/functionality_specified_partial_rollout.py`):

1. Для каждого шага вычисляется perplexity (строки 113-157):
   ```python
   think_ppl = np.exp(np.mean(entropies[think_start+1: think_end]))
   tool_call_ppl = np.exp(np.mean(entropies[tool_call_start+1: tool_call_end]))
   ```
2. Выбираются шаги с максимальной неопределённостью (строки 285-317):
   ```python
   branch_step = sorted(branch_step, key=lambda x: x['step_ppl'], reverse=True)[:topk]
   ```
3. На каждом выбранном шаге генерируются альтернативные продолжения:
   ```python
   rollout_single_traj(..., r['rollout'][:int(b['step_id'])], ...)  # обрезка до точки ветвления
   ```

**Режимы PPL:** `tool_call_ppl`, `think_ppl`, `mixed_ppl` (50/50), `all_ppl`

**Параметры по умолчанию:** `partial_sampling_topk=2` (2 точки ветвления), `partial_sampling_times_per_pos=3` (3 альтернативы на точку), `sampling_budget=8`

### 8.4 Open-World Memory

**Цель:** Документы → knowledge graph → агентные тренировочные данные.

Конвейер: потоки данных → структурированная «память» → формализация (тройки `сущность-отношение-сущность`) → синтез QA-пар, для которых гарантированно нужен многошаговый поиск.

Код не опубликован, но формат виден в `webshaper.500.jsonl`.

### 8.5 Двухстадийный CPT (32K → 128K)

- **Stage 1 (32K):** Короткие траектории (3-8 шагов). FAS-Planning + FAS-Reasoning. Цель: «грамматика» агентного формата.
- **Stage 2 (128K):** Полные траектории (15-30+ шагов). HAS данные. Цель: удержание агентного поведения на длинных горизонтах.
- **Эффект:** +3.3% Pass@1 vs одностадийный CPT. Обучение на обрезанных траекториях значительно хуже.

### 8.6 ReSum + ReSum-GRPO (Scaffold-уровневый midtraining)

**Цель:** Периодическое сжатие контекста + RL-адаптация к scaffold.

**Механизм** (из `WebResummer/src/summary_utils.py`):
- Каждые N шагов вызывается ReSumTool (30B модель) для сжатия в `<summary>...</summary>`
- Два режима: начальное сжатие (`QUERY_SUMMARY_PROMPT`) и инкрементальное (`QUERY_SUMMARY_PROMPT_LAST`)
- ReSum-GRPO: сегментация длинных траекторий по точкам сжатия + трансляция trajectory-level advantages
- Эффект: +4.5% plug-and-play, +8.2% с ReSum-GRPO

### 8.7 AgentFold — Self-Compressing Agent

**Цель:** Модель сама решает, что сжимать в контексте.

**Механизм** (из `AgentFold/infer.py`, строки 78-262):
На каждом шаге модель генерирует:
- `<think>` — рассуждение
- `<compress>` — JSON: `{"compress_range": [3,4,5], "compress_text": "Steps 3-5 established..."}`
- `<motivation>` — обоснование следующего действия
- `<tool_call>` или `<answer>`

Контекст форматируется как: `[Step 1]...full... [Compressed Step 2 to 5]...summary... [Step 6]...full...`

### 8.8 ISR/ISE Filtering (WebLeaper)

**Цель:** Курирование SFT-данных по эффективности.

- **ISR** = |найденные сущности ∩ целевые| / |целевые| (coverage)
- **ISE** = целевые сущности / шаги (efficiency)
- Фильтрация: ISR > 0.3, ISE > 0.1
- Hybrid Reward для RL: soft F-score с семантическим matching

### 8.9 SailorFog-QA — Data с управляемой неопределённостью

**Цель:** Вопросы с высокой начальной неопределённостью, требующие многошагового reasoning.

Формат (из `WebSailor/dataset/sailorfog-QA.jsonl`):
```json
{"question": "A certain project jointly led by a well-known West Coast university's
experimental physics laboratory became one of three key instruments...",
 "answer": "Helioseismic and Magnetic Imager"}
```

Прямые имена заменены описаниями (information obfuscation) — модель должна сначала вывести, что «West Coast university» = Stanford, затем искать.

### 8.10 Compressed Reasoning Aggregation (ParallelMuse)

**Цель:** Test-time агрегация множества траекторий через сжатие.

**Этап 1 — Report** (из `compressed_reasoning_aggregation.py`): Каждая траектория → структурированный отчёт (Solution Planning, Solution Methods, Final Reasoning).

**Этап 2 — Integration:** Множественные отчёты → критическая оценка → выбор лучшего ответа.
